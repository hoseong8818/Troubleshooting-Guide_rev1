# 명세: 트러블슈팅 엑셀 통합 도구

기능 폴더: `specs/001-trouble-merge` · 상태: 구체화 완료(보류 1건) · 원칙: `docs/constitution.md` · 요청: `docs/request.md`

기술 스택은 쓰지 않는다. 정하지 못한 것은 `[NEEDS CLARIFICATION]`으로 남기고, 구체화 단계에서 질문으로 채운다.

## 배경

설비 트러블슈팅 기록을 여러 사람이 각자 양식의 엑셀로 쓴다. 기록이 한곳에 모이지 않아 같은 설비의 반복 문제를 알아채기 어렵다. 엑셀 여러 개를 표준 컬럼의 한 표로 모으고 설비별로 분류해 보여 주는 도구가 필요하다.

## 사용자와 사용 장면

- **사용자**: 트러블슈팅 기록을 모아 보는 담당자 한 명. 회사 PC에서 직접 도구를 돌린다.
- **장면**: 팀원들이 보낸 엑셀 5~8개를 도구에 넣고, 통합 엑셀 한 개와 감사 결과를 받아 설비별로 훑어본다.

## 사용자 스토리

### US1 (P1) 엑셀 한 개를 표준 표로 바꾼다

담당자는 양식 A 엑셀 한 개를 넣으면 표준 컬럼 6개(설비, 일자, 증상, 원인, 조치, 분류)의 통합 시트를 받는다.

**수용 기준**
1. Given 양식 A 가짜 엑셀이 있고, When 도구를 실행하면, Then 통합 엑셀이 만들어지고 정답 파일과 한 행씩 일치한다.
2. Given 입력 엑셀의 데이터 행이 N개일 때(행 수의 정의는 FR-014), When 실행하면, Then 통합 시트의 데이터 행도 N개다.
3. Given 입력에 표준에 없는 컬럼이 있을 때, When 실행하면, Then 그 값이 '기타 항목' 칸에 `이름: 값` 형태로 보관된다.
4. Given 분류 이름이 변환 규칙 표에 있을 때, When 실행하면, Then 통합 시트의 분류가 표준 이름으로 바뀌어 있다.
5. Given 설비, 일자, 증상이 모두 같은 행이 둘 이상일 때, When 실행하면, Then 모든 행이 그대로 남고 해당 행들에 '중복 의심'이 표시된다. 행은 지우지 않는다.
6. Given 날짜 칸이 '2026-11-07', '2026.11.07', '2026/11/7'처럼 서로 다른 형식일 때, When 실행하면, Then 모두 `YYYY-MM-DD`로 통일된다.

### US2 (P1) 판단이 안 되면 '확인 필요'로 남긴다

설비를 정할 수 없는 행은 억지로 분류하지 않고, 어디가 문제인지 보이게 남긴다.

**수용 기준**
1. Given 설비 코드가 비어 있는 행이 있을 때, When 실행하면, Then 그 행이 통합 시트에 남고 설비 칸에 '확인 필요', 원래 값, 이유가 표시된다.
2. Given 설비 코드가 변환 규칙 표에 없을 때, When 실행하면, Then 같은 방식으로 '확인 필요'가 된다.
3. Given 분류 값이 변환 규칙 표에 없을 때, When 실행하면, Then 분류 칸에 '확인 필요'와 원래 값이 남는다.
4. Given 필수값(설비, 증상, 원인, 조치)이 비었거나, 일자에 값이 있는데 날짜로 해석할 수 없는 행이 있을 때, When 실행하면, Then 그 행도 '확인 필요'와 이유가 함께 남는다.
5. Given 사람이 변환 규칙 표에 한 줄을 추가했을 때, When 다시 실행하면, Then 해당 행이 자동으로 분류되고 '확인 필요'가 줄어든다.

### US3 (P2) 감사 결과를 받는다

담당자는 통합 결과를 믿어도 되는지 한눈에 볼 수 있는 감사 결과를 받는다.

**수용 기준**
1. Given 실행이 끝났을 때, Then 감사 결과에 입력 행 수, 출력 행 수, 일치 여부가 나온다.
2. Given 입력에 대응 규칙이 없는 컬럼이 있을 때, Then 감사 결과에 그 컬럼명이 나온다.
3. Given 필수값이 빈 행이 있을 때, Then 감사 결과에 행 번호와 컬럼명이 나온다.
4. Given '확인 필요' 행이 있을 때, Then 감사 결과에 건수가 나온다.
5. Given 숨긴 시트가 있을 때, Then 그 시트는 읽지 않고, 감사 결과에 파일명과 숨긴 시트 수가 나온다.
6. Given 열 수 없는 파일이 있을 때, Then 나머지는 처리하고, 감사 결과에 실패한 파일명이 나온다.
7. 감사 결과와 로그에는 셀 값이 없고, 파일명, 시트명, 행 번호, 컬럼명, 건수만 있다.
8. Given 대응 규칙 없음이나 양식 모호인 시트가 있을 때, Then 감사 결과에 그 시트가 파일 표시명과 시트 표시명으로 나온다.
9. Given 모든 파일이 실패했을 때, Then 통합 파일은 만들지 않고 감사 결과는 남기며 `처리 결과: 처리된 파일 없음`이 나온다.

### US4 (P2) 여러 파일과 새 양식을 합친다

담당자는 양식이 다른 파일 여러 개를 한 번에 넣어 하나의 통합 시트를 받는다. 새 양식이 생기면 컬럼 대응 규칙 표만 추가한다.

**수용 기준**
1. Given 양식 2종, 파일 5개 이상을 한 번에 넣었을 때, Then 모든 파일의 모든 행이 통합 시트 한 장에 모인다.
2. Given 새 양식 파일이 있을 때, When 그 양식의 컬럼 대응 규칙을 표에 추가하고 실행하면, Then 코드 수정 없이 통합된다.
3. Given 새 양식의 규칙이 아직 없을 때, When 실행하면, Then 그 파일은 조용히 빠지지 않고 감사 결과에 '대응 규칙 없음'으로 나온다.

## 실패하는 경우

- 입력 파일이 없거나 엑셀이 아니거나 열 수 없을 때: 그 파일만 건너뛰고 나머지는 처리한다. 실패한 파일명을 감사 결과에 남긴다. 모든 파일이 실패하면 통합 파일을 만들지 않고 실행을 멈춘다. 이때도 감사 결과는 남긴다.
- 출력 파일이 이미 있을 때: 덮어쓰지 않고 실행 시각을 붙인 새 이름으로 만든다.
- 모든 오류 메시지에는 셀 값이 들어가지 않는다.

## 요구사항

### 기능 요구
- **FR-001** 표준 컬럼은 설비, 일자, 증상, 원인, 조치, 분류 6개와 '기타 항목'이다.
- **FR-002** 설비는 설비 코드 컬럼을 기준으로 정한다.
- **FR-003** 표준에 없는 컬럼은 버리지 않고 '기타 항목'에 `이름: 값`으로 보관한다.
- **FR-004** 분류 이름은 변환 규칙 표로 통일한다.
- **FR-005** 판단이 안 되는 행은 빼지 않고 '확인 필요', 원래 값, 이유와 함께 남긴다.
- **FR-006** 입력 행 수와 출력 행 수는 같다.
- **FR-007** 새 양식은 컬럼 대응 규칙 표 추가만으로 처리한다.
- **FR-008** 실행이 끝나면 감사 결과를 낸다.
- **FR-009** 설비 코드는 영문과 숫자로 된 고정 형식(예: EQ-001)이다. 앞뒤 공백과 대소문자만 정리하고, 변환 규칙 표와 정확히 같을 때만 일치로 본다. 실제 형식은 사람이 나중에 알려 준다.
- **FR-010** 설비, 일자, 증상이 모두 같은 행은 지우지 않고 '중복 의심'으로 표시한다. 비교는 변환 후 설비, 정리한 일자, 앞뒤 공백을 뺀 증상으로 하고, 일자가 있는 행은 파일이 달라도 비교하고, 일자가 빈 행은 같은 파일의 같은 시트 안에서만 비교한다. 설비나 일자가 '확인 필요'인 행은 비교에서 뺀다.
- **FR-011** 날짜는 여러 형식을 읽어 `YYYY-MM-DD`로 낸다. 읽는 형식은 날짜형 셀, `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/M/D`, 엑셀 일련번호(정수), 시각이 붙은 값(시각은 버림)이다. 두 자리 연도와 `MM/DD/YYYY`는 읽지 않고 '확인 필요'다. 읽을 수 없는 값도 '확인 필요'다. 출력 일자 셀은 날짜형이 아니라 `YYYY-MM-DD` 문자열이다.
- **FR-012** 시트가 여러 개면 보이는 시트를 모두 읽는다. 숨긴 시트(`hidden`, `veryHidden` 모두)는 읽지 않고 감사 결과에 보고한다.
- **FR-013** 필수값은 설비, 증상, 원인, 조치다. 비어 있으면 '확인 필요'다. 일자 칸이 비어 있는 것 자체는 '확인 필요'가 아니고, 값이 있는데 날짜로 읽을 수 없을 때만 '확인 필요'다.
- **FR-014** 입력 행은 보이는 시트에서 헤더 아래의 행 중 모든 칸이 빈 행을 뺀 것이다. 병합 셀은 범위의 첫 칸 값을 범위 전체에 채워 읽는다. 수식 셀은 저장된 계산값만 읽고, 값이 없으면 빈 칸으로 보며 그 건수를 감사 결과에 낸다. '대응 규칙 없음' 파일, 양식이 모호한 파일, 숨긴 시트, 실패한 파일의 행은 입력 행 수에 넣지 않고 감사 결과에 따로 보고한다.
- **FR-015** '확인 필요' 사유가 여러 개면 '확인 필요 이유'에 설비, 일자, 증상, 원인, 조치, 분류 순서로 `; `로 이어 쓰고, '원래 값'에도 같은 순서와 구분자로 `컬럼: 값`을 쓴다. 분류가 비어 있는 것은 '확인 필요'가 아니다. '기타 항목'은 원본 컬럼 순서대로 `이름: 값`을 `; `로 잇고 값이 빈 컬럼은 생략한다.
- **FR-016** 통합 시트는 설비, 일자, 원본 파일, 원본 행 순으로 정렬한다. 설비가 '확인 필요'인 행은 맨 아래에 둔다. 같은 설비 안에서 일자가 '확인 필요'이거나 비어 있는 행은 일자가 있는 행 뒤에 둔다.
- **FR-017** 양식은 원본 컬럼명이 모두 헤더에 있는 양식 중 컬럼 수가 가장 많은 것으로 정한다. 동점이면 '양식 모호'로 감사 결과에 보고하고 그 파일은 건너뛴다. 컬럼 대응 표에는 헤더 행(기본 1)과 시트 이름(기본 보이는 시트 전체)을 적을 수 있다. 한 표준 컬럼에 원본 컬럼이 여럿 대응되면 처리하지 않고 감사 결과에 보고한다.
- **FR-018** 변환 규칙 표의 키는 앞뒤 공백을 빼고 소문자로 바꿔 비교한다. 같은 키가 표준 값을 달리해 두 번 나오면 실행을 멈추고 줄 번호만 보고한다.
- **FR-019** 실행은 `python -m trouble_merge --input <폴더 또는 파일...> --config config --out out`이다. 종료 코드는 0 정상, 1 일부 실패(열 수 없는 파일, 대응 규칙 없음 시트, 양식 모호 시트가 하나라도 있음), 2 전부 실패 또는 설정 오류다. 예외의 메시지와 종류는 출력하지 않는다.
- **FR-020** 가짜 데이터 생성 스크립트(`tools/make_fake_data.py`)는 이미 있는 `data/fake/` 파일을 덮어쓰지 않고, 파일이 있으면 중단한다.
- **FR-021 (값 정리)** 출력의 문자열 값은 앞뒤 공백을 뺀 값이다. 가운데 공백과 대소문자는 바꾸지 않는다. 설비와 분류는 FR-009, FR-004의 변환 규칙을 적용한 값이다.
- **FR-022 (확인 필요 셀)** '확인 필요'인 컬럼의 셀에는 문자열 `확인 필요`를 쓰고, 원래 값은 '원래 값'에 FR-015 형식으로 남긴다. 해당 행의 다른 컬럼 값은 그대로 둔다.
- **FR-023 (출력 파일 이름)** `--out` 폴더에 `merged.xlsx`, `audit_<실행 시각>.txt`, `names_<실행 시각>.txt`를 만든다. `merged.xlsx`가 이미 있으면 `merged_<실행 시각>.xlsx`로 만든다. 어떤 기존 파일도 덮어쓰지 않는다. 읽은 파일이 하나도 없으면(전부 실패) 통합 파일은 만들지 않고 감사 결과와 이름 대응표는 만든 뒤 종료 코드 2로 멈춘다.
- **FR-024 (감사 결과 형식)** 감사 결과는 줄마다 `이름: 값` 형식이다. 낼 줄은 입력 행 수, 출력 행 수, 행 수 일치(예 또는 아니오), 확인 필요 건수, 중복 의심 건수, 읽은 파일 수, 처리 결과, 실패한 파일(없으면 `없음`), 상한 초과 파일(파일 표시명과 사유 종류), 대응 규칙 없음 시트, 양식 모호 시트, 대응 중복 양식 시트, 대응 규칙 없는 컬럼, 필수값 빈 칸(파일, 시트, 행 번호, 컬럼명), 숨긴 시트 수와 파일별 숨긴 시트, 수식 값 없음 건수, 수식 방지 접두사 처리 건수다. `처리 결과: 처리된 파일 없음` 줄은 읽은 파일이 0개일 때만 내며, 이때 입력과 출력 행 수가 모두 0이라 `행 수 일치: 예`가 나오므로 정상 처리로 오해하지 않게 하는 줄이다. 감사 결과에는 셀 값이 나오지 않는다.
- **FR-025 (헤더 조사 보고서)** `python -m trouble_merge.survey --input <폴더 또는 파일...> --config <폴더> --out <폴더>`는 입력의 `.xlsx`에서 보이는 시트의 헤더 행만 읽고(데이터 행은 읽지 않는다. 병합 칸은 채우지 않는다), 헤더 이름 목록(빈 칸 제외, 순서 무관)과 컬럼 대응 표 판별 결과가 같은 시트끼리 한 양식으로 묶어 `--out`에 `survey_<실행 시각>.txt`와 `names_<실행 시각>.txt`를 만든다. 헤더 행은 컬럼 대응 표의 양식에 맞으면 그 양식의 헤더 행, 아니면 1행이다. 보고서는 줄마다 `이름: 값` 형식이며 조사한 파일 수, 읽은 파일 수, 건너뛴 파일(지원하지 않는 형식, 상한 초과, 열기 실패), 숨긴 시트 수, 헤더 없는 시트 수, 양식 수, 새 양식 수를 내고, 양식마다(시트 수가 많은 순, 같으면 먼저 나온 순으로 `양식 1`, `양식 2` ...) 파일 수·시트 수·컬럼 수, 현재 컬럼 대응 표와의 관계(`기존 양식 <이름>`, `새 양식`, `양식 모호`, `대응 중복`), 컬럼 목록, 시트 목록(앞 10개까지 내고 넘으면 끝에 ` 외 N개`를 붙인다. 개수는 `--max-sheet-list`로 바꾸며 0이면 전부), 가장 가까운 다른 양식과 컬럼 몇 개 차이인지(이름 목록의 대칭 차집합 크기), 새 양식이면 등록 컬럼이 가장 많이 들어 있는 기존 양식과 그 양식에서 빠진 등록 컬럼 수를 낸다. 셀 값은 내지 않고 이름 표시는 NFR-009를 따른다(등록되지 않은 컬럼은 위치, 파일명·시트명은 마스킹, `--show-names`로 실제 이름). 크기 상한은 NFR-007의 `--max-file-mb`, `--max-unzipped-mb`를 같은 기본값으로 받는다(데이터 행을 읽지 않으므로 행 수 상한은 없다). 통합 파일은 만들지 않으며 기존 통합 동작과 출력은 바꾸지 않는다. 종료 코드는 0 정상, 1 건너뛴 파일 있음, 2 읽은 파일 없음 또는 설정 오류이고, 예외의 메시지와 종류는 출력하지 않는다.
- **FR-026 (결과 컬럼 설정)** `--config` 폴더에 `output_columns.csv`(UTF-8 BOM, 컬럼: 순서, 표시 이름, 역할)가 있으면 통합 시트의 앞쪽 컬럼을 그 순서와 표시 이름으로 쓴다. 역할은 판정 컬럼(설비, 일자, 증상, 원인, 조치, 분류) 또는 `추가`다. 판정 컬럼 6개는 모두 정확히 한 번씩 있어야 하며 뺄 수 없다(확인 필요·중복 의심 판정은 표시 이름과 상관없이 역할로 한다). 역할이 `추가`인 컬럼은 `column_map.csv`의 '표준 컬럼' 칸에 그 표시 이름으로 지정할 수 있고, 지정된 원본 컬럼의 값은 '기타 항목' 대신 그 컬럼에 FR-021대로 정리해 넣는다(확인 필요 판정 없음). 표시 이름은 비어 있지 않고 서로 다르며 고정 컬럼(기타 항목, 확인 필요 이유, 원래 값, 중복 의심, 원본 파일, 원본 시트, 원본 행)과 겹치지 않아야 한다. 이를 어기거나 `column_map.csv`의 '표준 컬럼'이 판정 컬럼도 추가 컬럼도 아니면 설정 오류(종료 코드 2, 줄 번호만)다. 고정 컬럼은 지금 이름과 순서 그대로 결과 컬럼 뒤에 둔다. 이 파일이 있으면 통합 엑셀에 두 번째 시트 `컬럼 역할`(컬럼: 표시 이름, 역할)을 함께 쓰고, 게시판(FR-019 이후의 board)은 이 시트로 역할을 찾아 지금과 같은 화면을 만든다. 이 파일이 없으면 출력은 지금과 같다. 입력 행 수 = 출력 행 수 원칙은 그대로다.
- **FR-027 (컬럼 설정 창)** `python -m trouble_merge.setup_gui --input <폴더 또는 파일...> --config <폴더>`는 tkinter 창을 띄운다(표준 라이브러리만). ① 양식 찾기: FR-025와 같은 방법으로 헤더 행만 읽어 양식별 파일 수와 `새 양식`을 보여 준다. 헤더 행은 대응 표의 값 또는 1행이며 창에서 바꾸지 않는다(데이터 행을 화면에 보이지 않기 위함. 바꾸려면 사람이 `column_map.csv`를 고친다). ② 결과 컬럼: 판정 컬럼 6개의 표시 이름과 순서를 바꾸고, 추가 컬럼을 더하거나 뺀다. ③ 양식별 대응: 원본 컬럼마다 결과 컬럼 하나 또는 `기타 항목`(기본값)을 고른다. 추천은 결과 컬럼 이름 또는 이전에 저장한 대응의 원본 컬럼명과 앞뒤 공백·대소문자만 다른 경우에만 미리 채우고, 그 밖의 비슷한 이름은 묶지 않는다. 새 양식 이름은 `양식 N`으로 붙이고 창에서 바꿀 수 있다. 저장 전에 한 양식에서 두 원본 컬럼이 같은 결과 컬럼에 대응되면 저장하지 않고 겹치는 컬럼을 표시하며, 설비·증상·원인·조치에 대응이 없는 양식은 경고 후 저장을 허용한다. 저장은 `column_map.csv`(지금 형식)와 `output_columns.csv`(FR-026)를 UTF-8 BOM으로 쓰고, 기존 파일은 덮어쓰지 않고 `<이름>_<실행 시각>.csv`로 옮겨 보관한 뒤 새로 쓴다. 창은 실제 헤더 이름을 사람 PC 화면에만 보이며 셀 값은 보이지 않는다. 로그와 stdout·stderr는 safe_log 규칙(NFR-009)을 따른다. 판단 로직(양식 찾기, 추천, 검사, 저장)은 화면과 나눈 `setup_config` 모듈에 둔다. `run_merge.bat`은 설정이 있으면 `1 기존 설정으로 실행 / 2 설정 창 열기`를 묻고, 없으면 창을 열며, 창에서 `이 설정으로 통합 실행`을 고르면 통합으로 넘어가고 `저장만 하고 닫기`면 멈춘다. 맨 위 `GUI` 줄을 0으로 두면 창 없이 지금처럼 실행한다.
- **FR-028 (제외 시트)** `--config` 폴더에 `skip_sheets.csv`(UTF-8 BOM, 컬럼: 시트)가 있으면 이름이 같은(앞뒤 공백·대소문자만 정리) 보이는 시트는 통합과 헤더 조사에서 읽지 않는다(목차·요약 시트용). 감사 결과와 헤더 조사 보고서에 `제외한 시트 수: N` 줄을 내고, 제외한 시트는 '대응 규칙 없음'으로 세지 않으며 종료 코드 1의 원인이 되지 않는다. 파일이 없으면 지금과 같다.
- **FR-029 (로컬 서버와 HTML 설정 화면)** `python -m trouble_merge.server --input <폴더...> --config <폴더> --out <폴더> [--port 3456] [--merge]`는 표준 라이브러리 HTTP 서버를 `127.0.0.1`에만 연다(`--port 0`이면 빈 포트, 시작할 때 `주소: http://127.0.0.1:<포트>/` 한 줄을 낸다). `--merge`면 시작할 때 통합(FR-019)과 게시판을 `--out`의 `run_<실행 시각>` 폴더에 만든다. `/`는 가장 최근 `run_*`의 게시판을, 없으면 안내 화면을 보인다. `/setup`은 설정 화면이다: 양식(모양)마다 파일 수와 시트 이름, 원본 칸마다 예시 값(그 양식 첫 시트의 데이터 행에서 빈 칸이 아닌 값 앞 3개, 30자까지)과 결과 칸 고르기(판정 컬럼, 추가 컬럼, `따로 보관`=기타 항목), `이 모양은 통합하지 않음`(그 시트 이름을 `skip_sheets.csv`에 저장), 접어 둔 고급 칸(결과 컬럼 이름·순서·추가)을 한 화면에 보인다. 추천·검사·저장은 FR-027의 `setup_config`을 그대로 쓴다. 저장 뒤 `통합하고 게시판 보기`로 통합을 다시 하고 `/`로 간다. 예시 값은 그 화면 응답에만 담고 로그·파일·stdout·stderr에는 남기지 않는다. 안전: Host 머리글이 `127.0.0.1:<포트>` 또는 `localhost:<포트>`가 아니면 거부, 데이터를 바꾸는 요청은 POST와 `Content-Type: application/json`과 머리글 `X-Trouble-Merge: 1`이 있어야 하고 본문은 1MB까지, CORS 머리글은 내지 않으며 외부 주소를 불러오지 않는다. 서버 로그는 고정 문구(요청 종류와 상태 코드)만 낸다.
- **FR-030 (실행 파일 4개)** 저장소 루트의 `1_검사.bat`(FR-025 보고서를 만들고 열며 새 양식이 있으면 2번을 안내), `2_설정.bat`(서버가 꺼져 있으면 켜고 `/setup`을 연다), `3_서버실행.bat`(켜진 서버를 끄고 `--merge`로 다시 켠 뒤 `/`를 연다. 엑셀이 늘면 이것만 다시 실행), `4_서버종료.bat`(그 포트의 python 서버만 끈다)로 쓴다. 네 파일은 맨 위의 같은 네 줄(INPUT, CONFIG, OUT, PORT)만 고친다. 기본 경로는 예시 데이터이며 실제 데이터 경로로 바꾸는 것과 실제 데이터 실행은 사람이 한다(헌법 원칙 1). 서버는 별도 창에서 돌고 그 창을 닫아도 꺼진다.

### 비기능 요구
- **NFR-001 (보안)** 실제 엑셀은 AI가 읽지 않는다. 가짜 데이터로만 개발한다(원칙 1).
- **NFR-002 (로그)** 로그와 에러에 셀 값을 남기지 않는다(원칙 2). 가짜 데이터의 표식 값이 로그에 나오면 실패다.
- **NFR-003 (변경 금지)** 입력 파일은 읽기만 하고 수정하지 않는다. 정답, 테스트, 변환 규칙 표는 에이전트가 고치지 않는다(원칙 4).
- **NFR-004 (한국어)** 화면과 출력 문구는 한국어다.
- **NFR-005 (처리 시간)** 보류. 실제 데이터 규모를 사람이 회사 PC에서 재어 본 뒤 숫자로 정한다. 담당: 나, 시점: 실무 이관 전. 그 전까지 구현은 처리 시간으로 설계를 정하지 않는다.
- **NFR-006 (실행 환경)** 사내 PC에서 Python과 외부 패키지 openpyxl 하나만으로 돌릴 수 있어야 한다. 설치가 막히면 버전을 고정한 `uv run --with openpyxl==3.1.5 --with et_xmlfile==<고정 버전>`을 쓴다(사내 미러 또는 IT가 승인한 파일, 해시 검증). 가능한 범위는 plan에서 확인한다.
- **NFR-007 (입력 파일 방어)** 입력 엑셀은 신뢰할 수 없는 파일이다. `.xlsx`만 읽고 `.xlsm`·`.xls`는 열 수 없는 파일로 처리한다. 외부 링크와 매크로는 따라가지 않는다. 파일 크기, 압축 해제 후 크기, 시트당 행 수에 상한을 두고(숫자는 plan에서 정한다), 넘으면 그 파일만 건너뛰고 감사 결과에 파일명과 사유 종류만 보고한다. 이것은 처리 시간 상한(NFR-005)과 별개의 안전 상한이다. 크기와 행 수 상한은 명령줄 옵션 `--max-file-mb`, `--max-unzipped-mb`, `--max-rows`로 받고 기본값은 50, 200, 100000(데모용)이다. 실제 업무 이관 전에 정보보호 부서 기준으로 숫자를 정한다. 행 수는 파일을 읽은 뒤에 검사한다.
- **NFR-008 (출력 수식 주입 방지)** 통합 엑셀의 문자열 셀은 항상 문자열 형식으로 쓴다. 값이 `=`, `+`, `-`, `@`로 시작하면 앞에 `'`를 붙여 수식으로 실행되지 않게 한다. 원래 값은 바뀌지 않았음을 '원래 값' 규칙(FR-015)과 충돌 없이 보존한다(`'`는 표시용 접두사이며 감사 결과에 접두사 처리 건수를 낸다).
- **NFR-009 (이름 노출 제한)** 로그와 감사 결과의 컬럼명은 컬럼 대응 표에 등록된 이름만 그대로 낸다. 등록되지 않은 컬럼은 `열 3(C)`처럼 위치로만 적고, 컬럼명은 30자까지만 낸다. 파일명과 시트명은 기본이 마스킹(`file_01`, `sheet_01`)이고, 대응표는 `out/`의 감사 결과 옆 별도 파일로 낸다. 파일명과 시트명을 그대로 내는 옵션은 `--show-names`이며 사람이 켠다.
- **NFR-010 (실제 설정 분리)** 저장소 안의 `config/*.csv`는 가짜 값 전용이다. 실제 변환표와 컬럼 대응 표는 저장소 밖에 두고 `--config`로 지정한다. 실제 입력과 실제 결과도 저장소 밖에 둔다(헌법 원칙 1).
- **NFR-011 (통합 시트의 이름 노출)** 통합 시트의 '원본 파일'과 '원본 시트'에는 마스킹하지 않은 실제 이름이 들어간다. 통합 시트와 그 안의 셀 값은 입력과 같은 수준의 비밀로 다루고, 출력 폴더는 클라우드 동기화에서 제외한다. 로그와 감사 결과에 대한 NFR-009와 구분한다.

## 범위 밖

- 설비를 자유 텍스트에서 추정하는 일
- 실제 엑셀을 AI가 읽는 일
- 엑셀 안의 서식, 색, 차트의 보존
- 통합 결과의 시각화와 통계 화면

## 성공 기준

- **SC-001** 양식 A 가짜 입력의 통합 결과가 정답 파일과 한 행씩 일치한다.
- **SC-002** 모든 입력에서 입력 행 수와 출력 행 수가 같다.
- **SC-003** '확인 필요' 행은 원래 값과 이유가 모두 채워져 있다.
- **SC-004** 로그와 오류 메시지에서 표식 값이 0건 나온다.
- **SC-005** 변환 규칙 표에 한 줄을 추가하면 다음 실행에서 해당 행의 '확인 필요'가 사라진다.
- **SC-006** 새 양식을 코드 수정 없이 규칙 표 추가만으로 통합한다.
- **SC-007** 설비, 일자, 증상이 같은 행은 모두 '중복 의심'으로 표시되고 한 행도 지워지지 않는다.
- **SC-008** 숨긴 시트와 실패한 파일은 감사 결과에서 빠지지 않고 보고된다.
- **SC-009** `=`, `+`, `-`, `@`로 시작하는 입력 값이 통합 엑셀에서 수식으로 저장된 셀이 0개다.
- **SC-010** 상한을 넘는 파일, `.xlsm`·`.xls` 파일은 나머지 처리를 막지 않고 감사 결과에 보고된다.
- **SC-011** 등록되지 않은 컬럼명, 기본 설정의 파일명·시트명이 로그와 감사 결과에 그대로 나오지 않는다.

## 가정

- 양식 A 가짜 엑셀은 시트 1개, 1행이 헤더이고 컬럼명은 실제와 같다.
- 정답 파일은 사람이 만든다. 에이전트는 고치지 않는다.
- 첫 구현 범위는 양식 1종이고, 통과한 뒤 2~3종, 파일 5~8개로 늘린다.
