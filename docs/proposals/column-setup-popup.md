# 제안서: run_merge.bat 실행 시 컬럼 설정 창

> 상태: 제안(구현 전). 사람이 결정할 항목은 맨 아래 '결정할 것'에 모았다.
> 이 문서는 명세(spec.md)·작업(tasks.md)을 바꾸지 않는다. 채택하면 사람이 명세와 작업에 반영한 뒤 테스트부터 만든다.

## 1. 왜 필요한가

- 지금은 컬럼 대응을 `column_map.csv`에 사람이 손으로 적는다. 실제 엑셀이 수백 개이고 양식이 5개, 10개로 늘면 헤더를 일일이 열어 보고 적기 어렵다.
- 결과 시트의 컬럼(설비, 일자, 증상, 원인, 조치, 분류)과 순서가 코드에 고정되어 있어, 보여 주고 싶은 컬럼을 고르거나 순서를 바꿀 수 없다.
- 같은 뜻인데 이름이 다른 컬럼(`설비코드`, `호기`, `Equipment ID`)을 어떻게 묶을지 기준이 사람마다 달라질 수 있다.

## 2. 무엇을 하는가 (한 줄)

`run_merge.bat`을 더블클릭하면 설정 창이 뜨고 입력 폴더의 엑셀 **헤더(1행)만** 읽어 양식별로 묶어 보여 준다. 사람이 결과 컬럼의 개수·순서·이름과 원본 컬럼의 대응을 고르고 저장하면, 그 설정으로 통합을 진행한다.

## 3. 핵심 설계: '판정 컬럼'과 '보여 줄 컬럼'을 나눈다

현재 '확인 필요' 판정(설비 코드 미등록, 일자 해석 불가, 분류 미등록, 필수값 빈 칸 등)은 표준 컬럼 6개의 **역할**에 묶여 있다(`check.py`, `merge.py`). 컬럼을 마음대로 늘리고 줄이게 하면 이 판정이 깨진다. 그래서 둘을 나눈다.

| 구분 | 내용 | 사람이 바꿀 수 있는 것 |
|---|---|---|
| **판정 컬럼(역할)** | 설비, 일자, 증상, 원인, 조치, 분류 6개. 확인 필요 판정과 중복 의심 판정에 쓴다 | **표시 이름**과 **순서**. 빼기는 불가(빼면 판정이 안 됨) |
| **추가 컬럼** | 원본의 다른 컬럼(예: 에러코드, 담당자)을 '기타 항목'에서 꺼내 독립 컬럼으로 | 추가·삭제·이름·순서 모두 |
| **기타 항목** | 어느 컬럼에도 지정하지 않은 원본 컬럼을 `이름: 값`으로 모아 둠 | 없음(항상 마지막, 데이터를 버리지 않기 위함) |

예: 결과 시트를 `호기 | 발생일 | 현상 | 원인 | 조치 | 부품 | 알람코드 | 기타 항목` 순서로 보이게 할 수 있다. 내부적으로 `호기`는 '설비' 역할이라 설비 코드 판정을 그대로 받는다.

## 4. 화면 구성 (3단계)

**① 양식 찾기**
- 입력 폴더의 `.xlsx`를 훑어 **보이는 시트의 헤더 이름 목록**만 읽는다. 값은 읽지 않는다.
- 헤더 이름 목록이 같은 파일끼리 한 양식으로 묶는다. 예: `양식 1 — 파일 132개`, `양식 2 — 파일 47개` …
- 헤더가 1행이 아닌 양식은 헤더 행 번호를 고를 수 있다(그때만 위쪽 몇 행을 화면에 미리 보여 준다. 화면에만 표시하고 로그나 파일에는 남기지 않는다).

**② 결과 컬럼 정하기**
- 판정 컬럼 6개가 기본으로 있고 표시 이름을 바꾸고 위·아래 버튼으로 순서를 바꾼다.
- `+ 컬럼 추가`로 추가 컬럼을 만든다.

**③ 양식별 대응**
- 양식마다 원본 컬럼 옆에 드롭다운: `[결과 컬럼 중 하나] / 기타 항목`. 기본값은 `기타 항목`(버리지 않음).
- 이미 설정이 있으면 그 대응을 불러온다.
- 저장 전에 아래 검사를 통과해야 한다(5절).

저장 후 `이 설정으로 통합 실행` / `저장만 하고 닫기`를 고른다.

## 5. 컬럼 이름이 다를 때의 규칙

| 경우 | 처리 | 이유 |
|---|---|---|
| 뜻은 같고 이름이 다름(`설비코드`, `호기`, `Equipment ID`) | 양식마다 같은 결과 컬럼 '설비'로 지정 | 양식별 대응이 원래 이 문제를 위한 것 |
| 앞뒤 공백·대소문자만 다름(`조치내용`, `조치내용 `) | 같은 이름으로 보고 **추천**으로 미리 채움. 사람이 확인 | 지금 변환표 일치 규칙과 같은 정리 수준 |
| 비슷하지만 다름(`조치내용`, `조치 내용`, `처리내용`) | **자동으로 묶지 않는다.** 이전에 저장한 대응에 같은 이름이 있으면 추천만 표시 | 추측으로 묶으면 다른 뜻의 컬럼이 섞일 수 있음(헌법: 판단이 안 되면 사람에게) |
| 한 양식에서 두 원본 컬럼을 같은 결과 컬럼에 지정 | **저장 불가**, 어느 컬럼이 겹치는지 표시 | 지금 코드도 이런 양식은 처리하지 않음 |
| 판정 컬럼(설비·증상·원인·조치)에 지정한 원본이 없음 | 경고 후 저장은 허용. 그 양식의 행은 '확인 필요' | 행을 빼지 않는 원칙 유지 |
| 헤더 이름 목록이 다른 양식과 거의 같음(컬럼 하나 차이) | 별개 양식으로 표시하고 "양식 N과 컬럼 1개 차이" 안내 | 판별 기준(이름 목록이 같아야 같은 양식)을 바꾸지 않음 |
| 처음 보는 양식(설정에 없음) | 창에 '새 양식'으로 강조 | 지금은 실행 뒤 감사 결과의 '대응 규칙 없음'으로만 알 수 있었음 |

## 6. 저장하는 파일

`CONFIG` 폴더(실제 데이터면 저장소 밖 `real_config`)에 저장한다.

- `column_map.csv`: 지금 형식 그대로(양식, 원본 컬럼명, 표준 컬럼, 헤더행, 시트). '표준 컬럼' 칸에 판정 컬럼 역할 또는 추가 컬럼 이름이 들어간다.
- `output_columns.csv`(새 파일): 결과 컬럼의 순서·표시 이름·역할. 예:
  ```
  순서,표시 이름,역할
  1,호기,설비
  2,발생일,일자
  7,알람코드,추가
  ```
- 덮어쓰지 않는다. 기존 파일이 있으면 `column_map_<시각>.csv`로 보관한 뒤 새로 쓴다.
- 양식 이름은 `양식 1`, `양식 2`처럼 자동으로 붙이고 창에서 바꿀 수 있다.

## 7. 기술 선택

| 방안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **파이썬 tkinter** | 표준 라이브러리라 새 패키지 없음, 지금 코드(openpyxl)를 그대로 씀 | 화면이 투박함 | **권장** |
| PowerShell WinForms | 설치 없음 | 엑셀 헤더 읽기를 따로 만들어야 함, 테스트 어려움 | 비권장 |
| 로컬 웹 페이지(localhost) | 화면이 보기 좋음 | 파일 저장에 서버 코드 필요, 실제 데이터를 다루는 서버가 생김 | 비권장 |

- 화면 코드와 판단 코드를 나눈다. 헤더 읽기·양식 묶기·검사·CSV 쓰기는 별도 모듈(예: `setup_config.py`)로 만들어 `unittest`로 시험하고 화면(`setup_gui.py`)은 그 함수만 부른다.
- `run_merge.bat`은 설정이 있으면 `기존 설정으로 실행 / 설정 열기`를 묻고 없으면 바로 설정 창을 연다. 창 없이 돌리는 옵션(`--no-gui`)도 둔다.

## 8. 지켜야 할 것 (헌법과의 관계)

- **AI는 실제 엑셀을 보지 않는다.** 이 창은 사람이 자기 PC에서 띄우고 헤더를 읽는 것도 사람이 실행한 프로그램이다. 창의 내용을 AI에 붙여 넣지 않는다.
- **로그에 셀 값 금지.** 창에서 미리 본 행은 화면에만 표시한다. 로그는 지금처럼 `safe_log`만 쓴다.
- **데이터를 버리지 않는다.** 지정하지 않은 원본 컬럼은 항상 '기타 항목'으로 간다. 입력 행 수 = 출력 행 수는 그대로.
- **추측하지 않는다.** 비슷한 이름은 추천만 하고 자동으로 묶지 않는다.

## 9. 단계별 진행 (테스트 먼저)

1. **헤더 조사 보고서(창 없음)**: 입력 폴더의 양식 목록과 파일 수, 설정에 없는 새 양식을 텍스트로 낸다. 이것만으로도 "양식이 몇 개인지" 문제가 풀린다.
2. **결과 컬럼 설정(`output_columns.csv`)**: 순서·표시 이름·추가 컬럼을 코드에 반영한다. 기존 정답 파일과 테스트는 설정이 없을 때 지금과 같은 결과가 나와야 한다.
3. **설정 창(tkinter)**: 1·2를 화면으로 묶는다.
4. **`run_merge.bat` 연결**: 실행 시 창을 띄우고 저장 후 통합으로 넘어간다.

각 단계는 비교 테스트를 실패 상태로 먼저 커밋한 뒤 구현한다. 2단계는 결과 시트 모양을 바꾸므로 명세(FR) 추가와 정답 파일 추가가 필요하고 이는 사람이 확정한다.

## 10. 결정할 것 (사람)

1. 판정 컬럼 6개를 **빼는 것**까지 허용할지(권장: 불허, 이름·순서만 변경)
2. 비슷한 이름 추천의 범위(권장: 공백·대소문자 차이와 이전에 저장한 대응만)
3. 1단계(헤더 조사 보고서)만 먼저 할지, 창까지 한 번에 할지(권장: 1단계 먼저)
4. 게시판(`board.html`)도 같은 표시 이름과 순서를 따를지
5. 명세·작업 문서에 새 FR과 Phase 12로 반영할지
